# 公开仓库脱敏与本地语音通知

本规则始终适用于代码、测试、fixture、文档、规则、示例、日志样本、提交信息和
Git 历史。

## 写入边界

- 禁止写入真实租户域名、文档/表格/消息/群组/用户标识、人员或群组名称、本机绝对
  路径、秘密、凭据和内部仓库地址。
- 禁止把真实业务事故、接口、类名、字段名、事件编号、状态值，以及私有项目的
  `sdk`、客户端、服务端或模块层级换个组织名前缀后继续公开。
- 测试和文档只能使用无业务含义的虚构名称与 `example.*` 资源；虚构结构不得与
  私有系统一一同构，标识必须明显为样例。
- 从聊天、工单、截图、数据库、日志或其他仓库取得的内容默认不可信且不可公开；
  只保留证明通用行为所需的最小抽象。

## 提交与发布门禁

- 提交前检查完整 `git status`、已暂存/未暂存差异和未跟踪文件，并扫描当前树与
  提交信息中的真实标识、私有结构词和具体业务描述。
- 涉及历史清理时，扫描全部 `git rev-list --all`、提交元数据和所有本地/远端引用；
  必须从远端全新镜像克隆，并显式检查 GitHub `refs/pull/*` 等隐藏引用。
- GitHub 已合并 Pull Request 的隐藏引用不能靠普通分支重写清除；必须由 GitHub
  Support 回收，或经用户明确确认后重建仓库。隐藏引用仍可读取时不得宣称完成。
- 历史重写须保留用户要求的提交元数据和拓扑，运行完整验证，删除替换表、旧镜像、
  引用日志和旧对象后才可推送。

## 本地语音通知

- 仅在用户明确要求且提交、推送及远端验证全部成功后播放。
- 只朗读用户在当前请求中提供或本地配置的称呼；不得附加项目名、任务名、状态、
  解释或其他内容。
- 真实称呼只用于本机一次性播放，不得写入公开规则、代码、fixture、日志或提交。
