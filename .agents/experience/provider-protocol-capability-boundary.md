# Provider protocol capability boundary

Model provider behavior belongs in a local protocol adapter, not in scattered
prompt patches.

- Resolve every runtime role through a named profile before building a request:
  role -> profile -> provider -> protocol -> capabilities -> codec.
- Treat Kimi as an `openai_chat` protocol with provider traits. When thinking is
  enabled and tools are present, provide `tools` but omit `tool_choice=required`;
  forced tool choice is an explicit compatibility mode, not the default agent
  loop behavior.
- Record the actual role, profile, provider, protocol, model, request ID, phase,
  attempt, finish reason, HTTP status, failure category, and recovery action in
  durable audit. Do not infer model identity later from stale environment vars or
  old fingerprints.
- Classify provider errors before queue retry. HTTP 400, auth/permission errors,
  profile/protocol mismatch, and quota/balance exhaustion are deterministic
  blockers; retrying the whole work item only repeats the same failure.
  Network, timeout, rate-limit, and overload failures may retry inside the model
  step budget first.
- Keep API keys in Keychain. `OPENAI_*` may be a migration input for `primary`,
  but must not remain the only long-term runtime configuration source.
- The model-visible status bar must be computed from Go runtime truth. It can
  tell the model current phase, remaining budget, completed checks, unknowns, and
  last failed gate; it must not be generated by summarizing untrusted chat or tool
  text.
